# Domain docs

## Layout

This repo uses a single-context layout:

- `GLOSSARY.md` at the repo root.
- ADRs under `docs/adr/`.

## Before exploring

Read the root glossary and ADRs relevant to the area being explored.

If these files do not exist, proceed silently. The domain-modeling
skill creates them lazily when terms or decisions are resolved.

## Vocabulary

Use glossary terms when naming domain concepts in issues, proposals,
hypotheses, and tests.

If a needed concept is missing, reconsider whether it belongs to the
project's vocabulary or note the gap for domain-modeling.

## ADR conflicts

Explicitly surface any conflict with an existing ADR. Identify the ADR
and explain why its decision should be reconsidered.
