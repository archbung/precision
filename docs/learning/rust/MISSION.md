# Mission: Maintain Precision in Rust

## Why
I know Precision's domain model and established its structured agent workflows. With a working MVP, I want to understand and maintain its Rust code myself and judge its quality using evidence.

## Success looks like
- Explain a command from CLI parsing through validation, SQLite storage, and integration tests.
- Make a small behavior change myself, using tests and compiler feedback.
- Explain ownership, borrowing, enums, traits, and errors in the code I change.
- Assess readability and idiomatic Rust with explicit tradeoffs; measure realistic workloads before recommending performance changes.

## Constraints
- Rust beginner with Haskell and Ruby experience; comfortable with Git, terminal commands, SQL, and unit tests. Has written Rust hello world and compiled Precision several times. Aim for 30-minute lessons.
- One tightly scoped concept per lesson; predict, explain, attempt, then receive feedback.
- Hints before solutions. The learner implements exercises.
- Existing code is material to examine, not an endorsed model of Rust.

## Out of scope
- A broad refactor or full audit during setup.
- Mixing learning milestones with engineering improvement issues.
